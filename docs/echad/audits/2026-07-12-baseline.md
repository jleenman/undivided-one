Access window: 2026-07-12, Europe/Amsterdam. Live pages were inspected in a real browser before content research. After the initial local checkout proved obsolete, the user designated Nuxt as the source; `origin/main` was fetched and the bootstrap moved to current commit `d3ade65`.

## Executive finding

Current `origin/main` is the canonical implementation: a static bilingual Nuxt 3 site with local Markdown, PDFs, tests, and GitHub Pages deployment. The live routes, headings, key passages, metadata, and footer architecture match this source in spot checks. The earlier local Payload checkout was 19 commits behind and is intentionally excluded from the program. No canonical content was changed.

## Repository structure and workflow

- Framework: Nuxt 3.17, Vue 3.5, Tailwind; strict TypeScript.
- Package manager: npm with `package-lock.json`; install via `npm ci`.
- Content: `content/{nl,en}/{start,argument,essay,confession}.md`.
- Routes: explicit bilingual Vue pages under `pages/nl/` and `pages/en/`, plus `/`.
- Downloads: four PDFs under `public/downloads/`.
- Rendering: local Markdown parser and local SV/KJV scripture popovers in `utils/`.
- Build/export: `npm run generate` to `.output/public`; `npm run build` also exists.
- Tests: Vitest (`npm test`) for Markdown, route/content presence, and UI contracts; typecheck via `npm run typecheck`.
- Deployment: `.github/workflows/pages.yml` runs `npm ci` and `npm run generate`, then deploys GitHub Pages on every push to `main`; manual dispatch is enabled.
- Existing governance: `AGENTS.md` was stale Payload guidance despite Nuxt source and has been replaced with concise Nuxt/Echad rules.

## Essay measurement and compression target

Two baselines are retained:

- **Public rendered baseline:** Unicode word tokens from live `<main>`, including displayed TOC and verse widgets because visitors encounter them. NL 12,644; EN 12,682.
- **Editorial source baseline:** Markdown body excluding frontmatter. NL 9,030; EN 8,655.

The required 25–35% reduction should be measured on both. Editorial NL target: **5,870–6,773 source words**; public rendered target: **8,219–9,483 words**. English currently has 375 fewer source words than Dutch (−4.2%) but 38 more rendered words because localized scripture widgets differ. Both source essays have 43 headings and jump from 7.1 to 7.3, indicating stale/missing 7.2 numbering.

## Content risks

P0/P1 risks: false lexical `echad`/`yachid` contrast; exclusive John 14:9/10:30 deductions; Spirit subject-language; Hebrew/Greek binary; oversimplified Trinity origins; “another Jesus” rhetoric; undefined identity/multidimensional terms; Rev 1:1 and 5:6 grammar; Jude 5 copyist motives; overgeneralization from the Comma Johanneum. See `CLAIM-REGISTER.md`.

## Technical risks

- GitHub Pages deploys every merge/push to `main`, so the no-auto-merge gate is essential.
- No lint script exists; formatting/lint coverage is absent rather than passing.
- Tests are mostly source-contract/unit checks; there is no browser e2e, link checker, accessibility audit, or PDF parity test.
- `maximum-scale=1, user-scalable=no` in viewport metadata is an accessibility risk to audit under ECHAD-013.
- `typescript.typeCheck` is false during generate, so `npm run typecheck` must remain a separate required check.
